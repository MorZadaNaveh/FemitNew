## Hard scope boundaries (do not cross without explicit new instruction)

- **Design/theme only.** No customer data, no order data, no payments/checkout settings — ever.
- Product/content work (drafts, bundles) is the one exception, explicitly approved — see "Products & bundles" below. Still never touches payments.

## Language & direction

- Site is **Hebrew-only**. The only Latin-script text anywhere should be the brand name **"Femit"**.
- Theme is hardcoded RTL: `layout/theme.liquid` sets `<html lang="he" dir="rtl">` (the dev store's default language is English, so this can't rely on store locale settings).

## Workflow rules

- **Pull before push**: always `shopify theme pull` the current remote theme before pushing new code, so any content edits made by the user directly in the Shopify theme editor (images, text) aren't clobbered.
- All text, images, colors, and repeatable content are exposed as section `{% schema %}` settings/blocks so the user can edit everything themselves in the theme customizer without touching code.

## Products & bundles

- Only real, existing products are shown as purchasable — never invent fictional products.
- **Bundles** (e.g. "Trip bundle", "Divorce bundle") combine multiple real existing products under a new curated name: create as a real new product, price = sum of the component products' prices (no discounting), status **Draft** (not visible/purchasable) until the user approves and flips it live.
- **Articles** are different: it's fine to write new original articles matching the placeholder titles from the Stitch design, shown *alongside* (not replacing) the user's real articles.
